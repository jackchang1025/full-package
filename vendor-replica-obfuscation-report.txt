【混淆原因分析】

1. 【自定义方法爆炸】(OppoEngine, VivoEngine)
   
   原因：
   - OPPO ColorOS 有多个 app 管理界面
     → PowerControlActivity (com.oplus.battery)
     → Settings 中的 InstalledAppDetailsTop
     → StartupAppListActivity
     → 多个 AlertDialog 变体 (androidx.appcompat, coui 库等)
   
   - Vivo 有 3 套保活系统并存
     → Settings (standard Android)
     → Vivo PermissionManager (软权限)
     → Vivo ABE (Excessive Power Manager)
     → iQOO PowerSaving (子品牌定制)
   
   对策：
   → 抽象 ListenWindow 匹配器，减少重复代码
   → 使用配置驱动代替硬编码方法

2. 【状态机过度设计】(HuaweiEngine, VivoEngine)
   
   Huawei 状态：UNKNOWN → MAIN_APP → BACKUP_APP
   对应处理流程：
   - 启动主应用设置
   - 点击"手动管理"
   - 等待对话框并点击确认
   - 重复对备用应用
   
   Vivo 状态更复杂：
   - prepareInAppDetailSetting
   - prepareInAppPermissionManage
   - prepareInAppPermissionDetail
   - prepareInExcessivePowerManager
   - prepareInExcessivePowerDescription
   - prepareInAppPowerRank
   - prepareInPermissionAllowDialog
   共 7 个不同的窗口状态 + "未知" 态

3. 【权限维度碎片化】(XiaomiEngine, VivoEngine)
   
   Xiaomi:
   - 自启动 (AutoStart)
   - 关联启动 (RelateStart)
   - 完全后台 (FullBackground)
   - 电量消耗 (PowerConsumption)
   
   Vivo:
   - 自启动
   - 关联启动
   - 完全后台
   - 弹窗权限 (PopupInBackground) ← 额外！
   
   导致字段数线性增长
