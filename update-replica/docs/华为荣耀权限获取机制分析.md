## 一、执行架构

HuaweiSteps 的 `executeAll` 方法是一个**11 步顺序编排器**，按固定顺序执行所有权限获取：

```
executeAll (m212162a9)
│
├─ Step 1:  Honor? → executeHonorBasicPermissions
│           Huawei? → executeHuaweiBasicPermissions
├─ Step 2:  executeBatteryWhitelist
├─ Step 3:  executeBatteryOptimization
├─ Step 4:  executeAutoStart
├─ Step 5:  executeNotificationListenerPermission (仅 Honor)
├─ Step 6:  executeOverlayPermission
├─ Step 7:  executeNotificationPermission
├─ Step 8:  executeAllFilesAccess
├─ Step 9:  executeClearRecentTasks
│           └─ tryLockAppInRecents
├─ Step 10: handleHonorGalleryPermission (仅 Honor)
└─ Step 11: 完成 banner
```

每步之间 100ms 延时（`b81.m36683b1(100, cont)`），每步完成后写 SharedPreferences 标记防止重复执行。

## 二、权限获取机制分类

### 机制 A — 无障碍 UI 文本搜索点击

通过 `AccessibilityNodeInfo.findAccessibilityNodeInfosByText()` 定位 UI 节点，再 `performAction(ACTION_CLICK=16)` 点击。

**核心手法**：
- 搜索系统设置中的中文/繁体/英文开关文本
- 不可点击节点：向上遍历最多 5 层 parent 找可点击祖先
- Switch 控件匹配：通过 8 个 className 识别开关组件

**Switch 控件类名数组** (`f55054c0`)：
```
com.huawei.hwswitchwidget.HwSwitch     ← 华为定制
com.hihonor.widget.Switch               ← 荣耀定制
com.hihonor.android.widget.Switch        ← 荣耀新版
androidx.appcompat.widget.SwitchCompat   ← AndroidX
android.widget.Switch                    ← AOSP
android.widget.CheckBox                  ← 复选框
android.widget.ToggleButton              ← 切换按钮
android.widget.CompoundButton            ← 通用复合按钮
```

**使用此机制的权限**：全部 11 步均依赖此机制作为主要或辅助手段。

### 机制 B — Intent 直连系统 Activity

通过 `startActivity(Intent)` 直接跳转到系统设置的特定页面，绕过逐级导航。

#### B.1 标准 Android Settings Action

| Intent Action | 目标权限 | 使用步骤 |
|--------------|---------|---------|
| `android.settings.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` + `package:` URI | 电池优化白名单 | Step 2 |
| `android.settings.SETTINGS` | 设置主页（前置导航） | Step 3 |
| `android.settings.action.MANAGE_OVERLAY_PERMISSION` | 悬浮窗 | Step 6 |

### 机制 D — 坐标点击 / 手势

通过 `AccessibilityService.dispatchGesture(GestureDescription)` 在屏幕绝对坐标上执行点击或滑动。当 Accessibility 文本搜索失败时作为 fallback。

**实现方法**：`m212199f6(x, y, count)` / `m212200f7(x, y)`
```java
Path path = new Path();
path.moveTo(x, y);
GestureDescription gesture = new GestureDescription.Builder()
    .addStroke(new StrokeDescription(path, 0, 50/*ms*/))
    .build();
dispatchGesture(gesture, callback, handler);
```

#### D.1 权限弹窗坐标映射

**运行时权限弹窗**（根据权限类型动态选择坐标）：

| 位置 / 存储 | (65%, 77%) |

### 机制 E — 多机制组合

绝大多数权限获取采用组合策略，遵循 **B → A → D** 的降级回退链：

```
1. [B] Intent 打开目标设置页面
2. [A] 文本搜索定位目标节点 → performAction(CLICK)
3.      失败 → 遍历 parent 找可点击祖先
4.      失败 → [A] Switch className 匹配
5.      失败 → [D] 坐标点击 fallback
6.      失败 → [A] 滚动 + 重试
7. 外层重试（2-4 次完整流程）
```

### 权限 6 — 悬浮窗（SYSTEM_ALERT_WINDOW）

| 维度 | 详情 |
|------|------|
| **Android 权限** | `android.permission.SYSTEM_ALERT_WINDOW` |

5. **[A]** `performAction(ACTION_SET_TEXT=2097152, Bundle{text=appName})` 输入应用名
6. **[A]** 点击搜索结果中的目标应用
7. **[A]** 匹配开关文本：

   "显示在其他应用的上层","在其他应用上层显示","显示在其他应用上层",

8. **[A]** `toggleSwitch(text, true)` 开启

10. **验证**：`isOnOverlayDetailPage` 确认在详情页
11. **重试**：4 次外循环

**安全意义**：悬浮窗权限允许 RAT 在任意应用上层绘制 UI（钓鱼覆盖/注入页面）

### 权限 7 — 关闭通知渠道（隐身操作）

| 维度 | 详情 |
|------|------|
| **操作目标** | **关闭** RAT 自身 `"OFF"` 通知渠道，防止在状态栏暴露 |
| **方法** | `m212171b8` (executeNotificationPermission) |
| **机制** | **E = B + A** |
| **SP 标记** | `"notification_completed"` |

**执行流程**：
1. **[B]** `Intent("android.settings.CHANNEL_NOTIFICATION_SETTINGS")` + extras：
   ```
   "android.provider.extra.APP_PACKAGE" = packageName
   "android.provider.extra.CHANNEL_ID"  = "OFF"
   ```
2. **[A]** 等待 800ms → 轮询检测 `"允许通知"` 文本（最多 6 次）
3. **[A]** `toggleSwitch("允许通知", false)` — **关闭**开关（注意是 false）
4. **重试**：2 次，每次 BACK 返回重进

> ⚠️ **关键反常行为**：此步骤**关闭**通知而非开启，是 RAT 隐身策略的一部分——隐藏前台服务通知。

### 权限 9 — 反最近任务清理 + 进程锁定

| 维度 | 详情 |

5. **[D]** 垂直下拖 (centerX, 30%h→65%h, 500ms) 触发锁定图标
6. **[A]** 验证锁定状态（多语言）：
