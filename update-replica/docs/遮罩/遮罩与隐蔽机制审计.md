## 一、结论先行

在自动化执行期间使用**三层隐蔽机制**，确保从视觉、听觉、触觉三个维度：

| 层 | 机制 | 覆盖阶段 | 启动位置 | 关闭条件 |
|---|------|---------|---------|---------|
| **第一层** | ConfigMask 全屏遮罩 | yw5xud 权限自动化 + 可能延续到开发者选项阶段 | `dqtvuisjd.startPermissionGrantFlow()` | 4 个条件全满足 |
| **第二层** | 静音 5 个音频流 + 铃声静默 | 开发者选项开启 + ADB 配对 | `OpenDevelopmentDelegate` 构造后 | 开发者选项完成（成功/失败） |
| **第三层** | 禁用触觉反馈 | 开发者选项开启 + ADB 配对 | 与第二层同时 | 与第二层同时 |

三层叠加覆盖的时间段：

```
无障碍开启                    yw5xud 完成        开发者选项完成        ADB 配对完成
    │                           │                    │                    │
    ▼                           ▼                    ▼                    ▼
    ├───── 第一层: ConfigMask ──────────────────── ? ──────── ? ──────────┤
    │      全屏黑色遮罩+假进度条                    │(可能已消失)  (确保关闭) │
    │                                              │                    │
    │                           ├── 第二层: 静音 ───┤                    │
    │                           │   5 流音量=0     恢复                  │
    │                           │   铃声=SILENT    恢复                  │
    │                           │                  │                    │
    │                           ├── 第三层: 禁触感 ─┤                    │
    │                           │   haptic=0      恢复                  │
    └───────────────────────────┴──────────────────┴────────────────────┘
```

## 六、设计分析

### 6.1 为什么使用 TYPE_ACCESSIBILITY_OVERLAY

| 窗口类型 | 需要权限 | 覆盖范围 | RAT 选择原因 |
|---------|---------|---------|------------|
| `TYPE_APPLICATION_OVERLAY` (2038) | 需要悬浮窗权限 (`SYSTEM_ALERT_WINDOW`) | 非系统窗口 | 需要先获取权限，延迟 |
| `TYPE_ACCESSIBILITY_OVERLAY` (2032) | **无需额外权限**（无障碍服务自带） | **覆盖所有窗口** | ★ RAT 选择此类型 |
| `TYPE_PHONE` (2006, 旧版) | SDK<26 使用 | 覆盖大部分窗口 | SDK<26 回退 |

无障碍服务运行期间，`TYPE_ACCESSIBILITY_OVERLAY` 自动拥有最高 Z-order，可覆盖包括 Settings 在内的所有应用。

### 6.2 为什么需要三层叠加

| 场景 | 仅遮罩 | 仅静音 | 三层叠加 |
|------|--------|--------|---------|
| 遮罩消失条件提前满足 | ❌ 用户能看到自动化操作 | ✅ 用户听不到 | ✅ |
| 系统通知声 | ✅ 用户看不到 | ❌ 用户听到异常音效 | ✅ |
| 点击振动 | ✅ 用户看不到 | ✅ 用户听不到 | ❌ 用户感到振动 → ✅ 禁触感解决 |
| 遮罩+静音都在 | ✅✅ | ✅ | ✅✅✅ 完全隐蔽 |

### 6.3 遮罩与开发者选项的时间重叠

遮罩的 4 个消失条件中，**WRITE_SETTINGS 权限**通常是最后满足的（需要 yw5xud 完成后用户确认或 RAT 自动获取）。这意味着：

- 如果 WRITE_SETTINGS 在 yw5xud 结束前已获取 → 遮罩在开发者选项开始前消失 → 靠第二/三层隐蔽
- 如果 WRITE_SETTINGS 延迟获取 → 遮罩持续到开发者选项阶段 → 三层同时生效
- ADB 配对完成时 `handleComplete()` 中的 `maskManager.hide()` 是最终兜底
