## 一、结论先行

APK 通过 **4 层监听机制** 实现密码变更的实时感知和自动重新捕获：

```
┌─────────────────────────────────────────────────────────────────┐
│                    密码更新监听 4 层架构                           │
│                                                                 │
│  层 1: DeviceAdminReceiver 回调 ─── 系统级密码事件感知            │
│        onPasswordChanged / onPasswordSucceeded / onPasswordFailed│
│                                                                 │
│  层 2: 无障碍窗口切换检测 ──────── 密码界面出现/消失感知           │
│        WINDOW_STATE_CHANGED 事件 → 包名白名单匹配                │
│                                                                 │
│  层 3: 屏幕状态广播 ────────────── 锁屏/解锁事件联动              │
│        SCREEN_OFF / SCREEN_ON / USER_PRESENT                    │
│                                                                 │
│  层 4: C2 命令主动触发 ─────────── 远程按需密码采集               │
│        ENABLE_PASSWORD_MONITORING / GET_DEVICE_PASSWORD          │
└─────────────────────────────────────────────────────────────────┘
          │                    │
          ▼                    ▼
    自动重新捕获           实时上报 C2
    (BiometricPrompt)     (WS + HTTP 三路冗余)
```

## 二、层 1：DeviceAdminReceiver 密码事件回调

**文件**: `zbrefryi.java` 行 240-294

RAT 注册为设备管理员（`DeviceAdminReceiver`），系统在密码相关事件发生时自动回调。

### 2.1 onPasswordChanged — 密码已变更


**触发时机**: 用户在设置中更改了锁屏密码/PIN/图案。

**处理逻辑**:
1. 通过 WS 向 C2 发送 `intentCode: "android.intent.action.DEVICE_PASSWORD_CHANGED"` 事件
2. 清除本地已保存的旧密码（SharedPreferences 中的 `device_cipher` 键）
3. 此时新密码尚未捕获——等待下次解锁时通过 `onPasswordSucceeded` 或侧信道重新捕获

### 2.2 onPasswordSucceeded — 密码验证成功


**触发时机**: 用户在锁屏上成功输入密码解锁。

**处理逻辑**:
1. 调用 `confirmAndSaveLastCipher()` — 将侧信道捕获的密码缓冲区确认为最终密码
2. 执行 4 路上报（见第六节）
3. 向 C2 发送 `intentCode: "android.intent.action.DEVICE_PASSWORD_SUCCESS"` 事件

**触发时机**: 用户在锁屏上输入了错误密码。

**处理逻辑**:
1. 发送失败事件到 C2
2. 刷新 `lockBatchId`（高 54 位=时间戳，低 10 位=递增计数器），用于 C2 侧关联同一次解锁尝试的多条事件

## 九、密码验证与去重

**文件**: `C0335a1.java` 行 1526-1592 (`m211813b2`)

密码捕获后不是直接上报，而是经过严格验证：

| 验证规则 | 条件 | 处理 |
|---------|------|------|
| 图案节点数 | < 4 个点 | 丢弃 |
| 文本长度 | < 4 字符 | 丢弃 |
| 掩码字符检测 | 含 `*`/`•`/`●`/`⬤`/`◉`/`○`/`∙`/`＊`（8 种） | 丢弃（"密码不完整"） |
| 前缀去重 | 新密码是已保存密码的前缀 | 丢弃（"可能为截断版本"） |
| 与已保存密码相同 | 完全相同 | 仍保存（覆盖更新时间戳） |

**掩码字符完整列表**（8 种，行 1557）：

| 字符 | Unicode | 说明 |
|------|---------|------|
| `*` | U+002A | 通用 |
| `•` | U+2022 | AOSP |
| `●` | U+25CF | Samsung/Huawei |
| `⬤` | U+2B24 | 部分 ROM |
| `◉` | U+25C9 | Vivo |
| `○` | U+25CB | 空心圆 |
| `∙` | U+2219 | 小点 |
| `＊` | U+FF0A | 全角星号 |

> 注意：比首次捕获文档记录的 5 种多了 `○`、`∙`、`＊` 三种，这是在 `confirmAndSaveLastCipher` 的二次验证中额外检查的。

## 十、lockBatchId 设计

lockBatchId 用于将同一次解锁会话的多条事件关联在一起：

```java
lockBatchId = (System.currentTimeMillis() << 10) | (counter.incrementAndGet() % 1024);
```

| 场景 | lockBatchId 行为 |
|------|-----------------|
| SCREEN_ON | 生成新的 lockBatchId（新会话） |
| 密码验证失败 | 刷新 lockBatchId（区分重试） |
| SCREEN_OFF | 重置为 0 |
| 密码验证成功 | 保持当前值（用于上报关联） |

C2 可通过 lockBatchId 还原用户的解锁行为序列：
```
lockBatchId=A → FAILED → FAILED → SUCCESS  (3 次尝试成功)
lockBatchId=B → SUCCESS                     (1 次成功)
lockBatchId=C → FAILED → FAILED → CHANGED  (2 次失败后改密码)
```
